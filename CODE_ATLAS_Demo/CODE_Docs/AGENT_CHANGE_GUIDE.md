# 후속 수정 안내

1. 먼저 REQUIREMENTS.md와 MODULE_MAP.md를 읽고 바꿀 기능을 정한다.
2. 해당 기능의 service.py와 독립 CLI만 읽는다. UI 변경이면 stages.js, app.js 또는 views/render.js부터 확인한다.
3. CODE_Vendor는 기존 엔진의 원본이다. 일반 UI·자동화 기능을 추가할 때 수정하지 않는다.
4. 입력·출력 키를 유지한 채 기능을 수정한다. 계약 변경 시 스키마 버전과 해당 테스트를 함께 갱신한다.
5. 관련된 검증만 먼저 실행한다. 변경이 다른 단계에 영향을 줄 때 전체 파이프라인 검증을 수행한다.
6. 비밀번호는 소스·설정·로그에 넣지 않고 환경변수로 전달한다.
7. 서버와 사용자 PC용 동일 처리 로직을 복사하지 않는다. 실행 방법만 구분한다.
8. 결과 파일 편집·조회 기능은 별도 프로그램에 구현한다.
9. 최신 사용자 요청을 이 문서보다 우선한다. 미확정 항목을 구현 시 임의로 확정하지 말고 기본값과 한계를 기록한다.
